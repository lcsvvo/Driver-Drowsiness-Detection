# 하품 CNN 가중치 (DMD)

`src/train_yawn.py` 가 만든 하품 분류기. 눈 모델(`src/train_eye.py`)과 같은 방식으로
학습·평가했다. **아직 실사용에 넣을 수준이 아니다.** 왜 그런지는 §4 에 적었다.

생성: `python src/train_yawn.py --train face body`

---

## 1. 파일

`model/artifacts/` 아래에 있다. `.keras` 는 git 으로 추적되므로 `git pull` 하면 받아진다.
아래 숫자는 전부 **face test 1,131장, 임계값 0.50** 기준이다.

| 조건 | 학습 소스 | Recall | Precision | 정확도 | F1 | `.keras` |
|---|---|---|---|---|---|---|
| C `yawn_face+body__eval-face__gray128` | 정면 + 측면 합본 | **0.807** | 0.565 | 0.630 | 0.665 | **있음** |
| A `yawn_face__eval-face__gray128` | 정면만 | 0.691 | **0.623** | **0.669** | 0.655 | metrics 만 |
| B `yawn_body__eval-face__gray128` | 측면만 | 0.247 | 0.291 | 0.384 | 0.267 | metrics 만 |

가중치는 실제로 쓰는 C 만 들어 있다. A·B 는 평가 결과(`_metrics.json`)만 남겼고,
필요하면 `python src/train_yawn.py --train face` 로 몇 분 안에 다시 만들 수 있다.

**A(정면만)와 C(합본) 중 무엇이 낫다고 말하기 어렵다.** F1 이 0.655 대 0.665 로 사실상
같고, C 는 Recall 이 높은 대신 오경보가 많고 A 는 반대다. test 피험자가 4명뿐이라
이 차이를 구분할 만한 근거가 없다. 굳이 고른다면:

- **손으로 가린 하품을 놓치지 않는 게 중요하면 C** (손가림 Recall 0.784 vs 0.641)
- **오경보를 줄이는 게 중요하면 A** (실전 환산 Precision 0.244 vs 0.203)

지금은 C 를 넣어 뒀다. 손 가림은 얼굴 검출이 끊기는 구간이라 다른 신호로 메우기
어렵다고 봤기 때문이다. A 로 바꾸려면 위 명령으로 다시 만든 뒤 노트북의
`YAWN_MODEL_NAME` 만 바꾸면 된다.

B(측면만)는 정면 카메라에 쓸 수 없다는 것만 확인하는 대조군이다.

각 `.keras` 옆의 `_metrics.json` 에 임계값·혼동행렬·조건별 분해가 다 들어 있다.
숫자를 인용할 일이 있으면 이 문서가 아니라 그 파일을 정본으로 삼는다.

`02_INFER_YuNet.ipynb` 는 **C 를 쓰도록 연결해 두었다** (§5). 옛
`yawn_model.keras`(256 RGB, 프레임 전체 입력)도 그대로 남아 있고, 노트북의
`YAWN_MODEL_NAME` 만 바꾸면 입력 방식까지 같이 되돌아간다.

## 2. 데이터

`miniProject1/Dataset/processed` (DMD mosaic 에서 뽑은 얼굴/상반신 crop 9,650장).
데이터셋 자체의 설명은 그쪽 `README.md` 를 볼 것.

- **face** = 정면 얼굴 카메라, **body** = 우측 측면 상반신 카메라
- split 은 **피험자 단위**이고 눈 데이터셋의 `DMD_SPLIT` 과 같은 매핑이다.
  train 7명 / val 2명 / test 4명. test 는 학습에서 본 적 없는 사람들이다.
- 라벨은 DMD 공식 어노테이션의 `yawning/*` 구간. 사람이 눈대중으로 고른 것이 아니다.

## 3. 쓰는 법

```python
import tensorflow as tf
from eye_preprocess import preprocess_eye        # src/ 에 있다

model = tf.keras.models.load_model(
    "model/artifacts/yawn_face+body__eval-face__gray128.keras")

# 입력: 얼굴 crop(BGR) -> 128x128 그레이스케일, 0~255
x = preprocess_eye(face_crop, size=128, grayscale=True,
                   do_sharpen=False, input_is_bgr=True)

p = model(x[None, ...], training=False).numpy()[0]
p_yawn = p[0]            # class 0 = yawn, class 1 = no_yawn
is_yawn = p_yawn >= 0.50
```

**class 0 이 yawn 이다.** 눈 모델의 `class 0 = Closed` 와 같은 규칙이고,
`02_INFER_YuNet.ipynb` 도 `prediction[0]` 을 하품 확률로 읽는다. 순서를 뒤집으면
에러 없이 조용히 반대로 동작한다.

임계값은 **0.50 을 쓴다.** `metrics.json` 의 `threshold` 필드는 val 에서
Yawn-Recall 0.90 을 맞추도록 고른 값인데, 이 모델들에서는 그게 역효과였다.
A 조건은 임계값이 0.15 까지 내려가 정확도가 0.503 으로 떨어진다 — 거의 전부를
"하품"이라고 찍는 것과 같다. 눈 모델에서 잘 통한 임계값 선택 방식이 여기서는
통하지 않았고, 그대로 두되 쓰지는 않는다.

## 4. 성능 — 그리고 왜 아직 못 쓰는지

face test 1,131장 @0.50, 하품 종류별 Recall:

| 조건 | 손으로 가림 (n=259) | 손 없음 (n=255) |
|---|---|---|
| C face+body | 0.784 | 0.831 |
| A face only | 0.641 | 0.741 |
| B body only | 0.232 | 0.263 |

**좋은 소식**: C 는 손으로 입을 가린 하품을 안 가린 하품과 거의 비슷하게 잡는다
(0.784 vs 0.831). 얼굴 검출이 끊기는 프레임까지 고정 crop 으로 살려 둔 데이터셋
설계가 여기서 효과를 봤다. 측면(body) 데이터를 섞은 것이 여기에 기여한 것으로 보인다
— A 는 같은 항목이 0.641 로 눈에 띄게 낮다.

**나쁜 소식 두 가지.**

### (1) 사람마다 성능이 널뛴다

test 피험자별 정확도 (@0.50):

| 조건 | gB_6 | gC_13 | gE_29 | gZ_37 | 편차 |
|---|---|---|---|---|---|
| C face+body | 0.864 | 0.799 | 0.532 | **0.333** | std 0.213 |
| A face only | 0.673 | 0.574 | 0.939 | 0.456 | std 0.178 |

A 조건에서 gC_13 은 Recall 0.025 로 하품을 거의 못 잡고, gZ_37 은 Recall 1.000 /
Precision 0.447 로 거의 전부를 하품이라고 찍는다. 같은 모델이 사람에 따라 정반대로
망가진다.

**즉 합계 정확도는 "평균적으로 이만큼 한다"가 아니라 "이 4명에서 이랬다"는 뜻이다.**
모델이 입 모양이 아니라 사람·좌석·조명에 붙은 단서를 학습했다는 신호다.
train 피험자가 7명뿐이라 놀랄 일은 아니다.

### (2) 실전 Precision 은 표의 숫자보다 훨씬 낮다

test 의 하품 비율은 45% 인데 실제 운전 중에는 14% 안팎이다(데이터셋 README §6).
Recall 과 FPR 은 클래스 비율에 안 변하므로 환산할 수 있고, 그 값이
`metrics.json` 의 `precision_at_real_prior` 다.

| 조건 | test Precision | 실전(14%) 환산 Precision |
|---|---|---|
| A face only | 0.623 | **0.244** |
| C face+body | 0.565 | **0.203** |

**하품 경보 5번 중 4번이 오경보라는 뜻이다.** 이 상태로 단독 경보를 울리면 안 된다.

### 원인 추정

- **라벨 자체의 천장.** DMD 는 하품의 시작부터 마무리까지를 한 구간으로 잡아서
  `yawn` 라벨 프레임 중에 입이 안 벌어진 것이 섞여 있다(데이터셋 README §6 이 명시).
  프레임 단위 정확도는 여기서 막힌다. 이건 모델이 아니라 GT 의 성질이다.
- **피험자 7명.** 사람에 붙은 단서를 배우기 쉬운 조건이다. (1)의 직접적인 원인으로 보인다.
- **스크래치 학습.** Conv 3층짜리를 7명 데이터로 처음부터 학습했다. 구조를 눈 모델과
  똑같이 둔 것은 성능 때문이 아니라 두 모델의 차이가 데이터에서만 오게 하려는 것이었다.

## 5. 추론 노트북 연동 — crop 스케일을 맞춰야 한다

`02_INFER_YuNet.ipynb` 의 하품 경로를 이 모델로 바꿨다. 그 과정에서 걸린 함정 하나를
기록해 둔다. **학습 crop 과 추론 crop 이 다르면 모델이 조용히 망가진다.**

데이터셋은 세션 전체의 검출 박스를 **합집합**해서 만든 고정 박스 하나를 그 세션 내내
썼다(프레임마다 박스가 흔들리면 CNN 이 입 모양이 아니라 crop 위치 변화를 학습하므로).
실시간에는 프레임이 하나뿐이라 그 여유가 안 생긴다. 같은 여백식(좌우 18% / 위 15% /
아래 32%)을 프레임 하나에 그대로 적용하면 crop 이 학습 때보다 19% 타이트해진다.

train/val 12개 세션에서 재 본 값 (test 세션은 보지 않았다):

| | 고정박스 한 변 / 얼굴 높이 |
|---|---|
| 학습 crop (세션 합집합) | **1.82** (세션별 1.66 ~ 2.10) |
| 여백식을 프레임 하나에 적용 | 1.47 |

같은 test 프레임 1,131장을 두 경로로 돌린 결과:

| 경로 | Recall | Precision | 정확도 | F1 |
|---|---|---|---|---|
| 데이터셋 crop (학습이 본 것) | 0.807 | 0.565 | 0.630 | 0.665 |
| 실시간 경로 — 여백식 그대로 | 0.946 | 0.467 | **0.485** | 0.625 |
| 실시간 경로 — 스케일 보정 후 | 0.840 | 0.548 | **0.613** | 0.664 |

보정 전에는 얼굴이 학습 때보다 크게 찍혀서 모델이 하품 쪽으로 쏠렸다 — Recall 0.946 /
Precision 0.467 은 거의 전부를 하품이라고 찍는다는 뜻이고, 정확도가 하품 아님으로만
찍는 것보다 나빴다. 보정 후에는 오프라인 평가와 사실상 같아졌다.

그래서 `src/yawn_dataset.py` 에 함수가 두 개 있다.

- `yawn_crop_box()` — 데이터셋 생성 스크립트의 `square_box()` 를 표본 1개로 줄인 것.
  랜덤 박스 2,000개로 원본과 결과가 완전히 일치하는 것을 확인했다.
- `yawn_infer_box()` — **추론에서 쓸 것.** 위에서 잰 스케일(얼굴 높이 x 1.82)로 자른다.

> 프레임별 박스는 흔들린다. 두 경로의 확률 상관은 0.46, 판정 일치율은 0.73 으로
> 개별 프레임 예측은 꽤 다르다. 합계 성능만 같아진 것이다. 실시간 셀의 EMA 가
> 이 흔들림을 눌러 주지만, 얼마나 눌러 주는지는 영상 단위로 재 봐야 안다.

## 6. 다음에 할 것 (안 한 것)

1. **전이학습.** MobileNetV2 등 사전학습 backbone 을 붙이면 사람별 편차가 줄어들 가능성이
   가장 크다. 피험자 수가 적을 때의 표준 처방이다. **가장 먼저 해볼 것.**
2. **영상 단위 평가.** 이 문서의 숫자는 전부 프레임 단위다. `02_INFER_YuNet.ipynb` 의
   EMA 가 시간축으로 눌러 주므로 실시간 성능은 이보다 나을 것이고, 지금 숫자는 하한에
   가깝다. 하지만 얼마나 나은지, 오경보가 실제로 몇 초에 한 번 뜨는지는 영상을 통째로
   돌려 봐야 안다. **경보를 켜기 전에 이건 반드시 해야 한다.**
3. **RGB / 더 큰 입력.** 지금은 128 그레이스케일이다. `--rgb`, `--size` 플래그로 바로
   비교할 수 있다. 아직 안 돌려봤다.

## 7. 재현

```bash
python src/train_yawn.py --train face          # A
python src/train_yawn.py --train body          # B
python src/train_yawn.py --train face body     # C
```

데이터셋 위치는 관례 경로를 순서대로 찾는다. 다른 곳에 두었으면 `--dataset-root` 로 준다.
학습 없이 평가만 다시 하려면 `train_yawn.reevaluate(tag)`.
조건 비교표는 `train_yawn.compare()`.
